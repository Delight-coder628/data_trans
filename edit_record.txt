================================================================================
LongCat-Image-Edit-Turbo 昇腾NPU多卡并行推理改造 - 修改记录
================================================================================

改造目标：
  将模型不同组件加载到不同NPU卡上，替代原来的单卡+CPU offloading方案，
  以提高推理速度并减少单卡显存占用。

设备分配方案：
  npu:1 → Text Encoder + VAE（体积较小，共用一张卡）
  npu:2 → Transformer（最大组件，独占一张卡）
  npu:0 → 不使用（完全空闲）

【修改后】
def setup_environment():
    """设置运行环境 - 多卡并行模式"""
    # 设置各组件的目标设备，不使用0号卡
    # npu:1 承载 Text Encoder + VAE（体积较小，共用一张卡）
    # npu:2 承载 Transformer（最大组件，独占一张卡）
    device_te = torch.device('npu:1')
    device_transformer = torch.device('npu:2')

    print(f"Text Encoder / VAE 设备：{device_te}")
    print(f"Transformer 设备：{device_transformer}")

    # 设置随机种子以确保可重复性
    torch.manual_seed(42)
    if torch.npu.is_available():
        torch.npu.manual_seed(42)

    return device_te, device_transformer

【原因】原来只返回一个device对象(npu:0)，现在返回两个设备对象：
  - device_te (npu:1) 用于Text Encoder和VAE
  - device_transformer (npu:2) 用于Transformer
  不再使用npu:0，避免0号卡被占用。

    # enable_attention_slicing()和enable_vae_slicing()方法在此管道中不可用
    # CPU offload本身可用有效减少NPU内存占用，但是会导致推理速度较慢

【修改后】
    pipe = LongCatImageEditPipeline.from_pretrained(
        checkpoint_dir, 
        transformer=transformer, 
        text_processor=text_processor, 
        torch_dtype=torch.bfloat16,
    )

    # === 多卡并行：手动将各组件分配到不同设备 ===
    # 不再使用 pipe.to(device) 统一移动，而是分别放到各自的目标卡上

    # Text Encoder 放到 npu:1
    if hasattr(pipe, 'text_encoder') and pipe.text_encoder is not None:
        pipe.text_encoder = pipe.text_encoder.to(device_te)
        print(f"Text Encoder 已放置到 {device_te}")

    # VAE 放到 npu:1（与Text Encoder共用）
    if hasattr(pipe, 'vae') and pipe.vae is not None:
        pipe.vae = pipe.vae.to(device_te)
        print(f"VAE 已放置到 {device_te}")

    # Transformer 确保在 npu:2 上（load_model时已移动，此处再次确认）
    if hasattr(pipe, 'transformer') and pipe.transformer is not None:
        pipe.transformer = pipe.transformer.to(device_transformer)
        print(f"Transformer 已确认在 {device_transformer}")

    # 注意：不再使用 enable_model_cpu_offload()
    # 多卡部署已将组件分散到不同卡上，解决了显存问题
    # 同时避免了CPU offloading中CPU<->NPU的搬运开销，推理速度更快

    print("图像编辑管道创建完成")
    return pipe

【原因】这是最关键的改动：
  1. 删除了 pipe.to(device)，这会把所有组件移到同一设备
  2. 删除了 pipe.enable_model_cpu_offload()，这会导致CPU<->NPU搬运
  3. 改为手动将各组件分别放到目标设备：
     - text_encoder -> npu:1
     - vae -> npu:1
     - transformer -> npu:2
  4. 使用 hasattr 检查确保组件存在，避免属性不存在时报错

总结
================================================================================

核心改动：
  1. setup_environment() 返回两个设备对象 (npu:1, npu:2) 而非一个 (npu:0)
  2. load_model() 将transformer加载到npu:2
  3. create_pipeline() 手动将各组件分配到不同设备，替代 pipe.to(device) + cpu_offload
  4. perform_editing() 移除device参数
  5. main() 适配新的函数签名

预期效果：
  - 0号卡完全空闲
  - Text Encoder + VAE 在1号卡（约3-4GB显存）
  - Transformer 在2号卡（约12-16GB显存）
  - 推理速度提升（避免CPU<->NPU搬运开销）
  - 单卡显存占用降低

注意事项：
  1. 如果pipeline的__call__方法内部不会自动处理跨设备张量转移，
     可能需要修改pipeline源码，在组件调用前手动执行 tensor.to(device)
  2. 首次运行建议用 torch.npu.memory_stats() 监控各卡显存占用
  3. npu:1和npu:2之间会有少量张量传输，但比CPU offloading快得多
  4. 如果后续需要进一步优化，可考虑将Transformer做Tensor Parallelism分到更多卡
